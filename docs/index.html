DEConcord

A Python package for one question: if you analyse the same RNA-seq experiment with a different differential expression tool, a different significance cutoff or a different subset of samples, do you still reach the same conclusion?

Source on GitHub Install Limitations Cite

Why this exists

Most RNA-seq papers report the genes that one tool, run once, called significant. But DESeq2, edgeR and limma-voom make different statistical assumptions, and each is a reasonable choice. If a result depends on which one you picked, that is worth knowing before you build a story on it.

DEConcord does not replace those tools. It takes their result tables (or any table with a gene ID, a log fold change and a p-value) and measures how much they agree: which genes are significant in both, which in only one, whether shared genes move in the same direction, and how strongly the fold changes correlate.

What it found so far

Each tool was run separately with its own default settings on two public datasets: airway (human airway cells) and pasilla (fruit fly). Then every pair of tools was compared.

Agreement between tools, pair by pair. The Jaccard index is the share of significant genes the two tools have in common (1 = identical lists). Same direction is the share of genes significant in both whose fold changes point the same way.

The tools disagree about which borderline genes clear the significance cutoff, sometimes by a quarter of the list. They never disagreed about direction: no gene was called significantly up by one tool and significantly down by another.

I then pushed the comparison outside these two clean, balanced experiments, using subsets of a third public dataset (Bottomly): increasingly unbalanced groups, a technical covariate, and reads thinned to 25% and 5% of the original depth. Unbalanced groups hurt agreement the most (DESeq2 vs edgeR Jaccard fell from 0.93 to 0.70). Across all 24 comparisons, direction still agreed every time.

These are results on a handful of standard datasets, not a general law about these tools. All the scripts and full tables are in benchmarks/.

Using it

DEConcord needs Python 3.9 or newer.

git clone https://github.com/nezihcandikme/DeConcord.git
cd DeConcord
pip install -e .

Compare two result tables from Python:

import pandas as pd
from deconcord.concordance.methods import compute_de_concordance

deseq2 = pd.read_csv("deseq2_results.csv", index_col="gene_id")
edger = pd.read_csv("edger_results.csv", index_col="gene_id")

result = compute_de_concordance(
    deseq2, edger, name_a="DESeq2", name_b="edgeR",
    lfc_col_a="log2FoldChange", pvalue_col_a="padj",
    lfc_col_b="logFC", pvalue_col_b="FDR",
)
result["summary"]["jaccard_index"]
result["discordant_genes"]

Or from the command line, without writing any Python:

deconcord concordance deseq2_results.csv edger_results.csv \
    --name-a DESeq2 --name-b edgeR \
    --lfc-col-a log2FoldChange --pvalue-col-a padj \
    --lfc-col-b logFC --pvalue-col-b FDR \
    --out concordance_output

This writes a summary.json, a merged table of every gene with both tools' values side by side, and separate lists of the genes the tools agree and disagree on. A complete runnable example is in examples/quickstart.py.

What it can check

Method concordance
Two result tables for the same comparison: overlap of significant genes, fold-change correlation, direction agreement, and the exact genes behind each disagreement.
Threshold sensitivity
The same comparison across a range of significance cutoffs, to see which genes stay significant whatever reasonable cutoff you choose.
Pathway stability
Whether a pathway stays enriched when the gene list underneath it comes from a different tool.
Resampling stability
Reruns the analysis on subsets of samples (subsampling or leave-one-out) to see whether a gene's call depends on which samples happened to be collected.

To produce result tables in the first place, the package also includes a small analysis pipeline: input checks with specific error messages, sample quality control, normalisation, two simple differential expression tests, pathway enrichment, and volcano and PCA plots. It is there to support the comparisons, not to compete with DESeq2 or edgeR.

Limitations

  • The concordance results come from a few public datasets with simple two-group designs.
  • The analysis pipeline only handles two-group comparisons (with optional covariates): no paired samples, no designs with more than two conditions.
  • Resampling uses subsampling and leave-one-out, not a true bootstrap.
  • Pathway stability cannot tell when two enrichment tables were built from different gene-set collections, which would make the comparison meaningless.
  • The metrics are standard ones (Jaccard, correlation, direction agreement). No new statistical method is claimed.
